# 练了吗 Web v1 原型

一个手机宽度优先的 Next.js 原型，用来演示「练了吗」最核心的训练闭环：

**首页 / 今日页 → 开始训练 → 训练后回顾 → 次日恢复**

另外补了一个极简趋势页，用来快速看方向感。

## 技术路线

- Next.js 15
- TypeScript
- Tailwind CSS 4
- 本地 mock data + localStorage 演示状态

## 已实现页面

- `/` 首页 / 今日页
- `/train` 开始训练 / 训练记录页
- `/review` 训练后回顾页
- `/recovery` 次日恢复页
- `/trends` 趋势页（极简版）

## 这个原型重点保了什么

- 首页不是数据大盘，而是“今天下一步该做什么”
- 首页里可一键切换几种典型状态：新手 / 正常 / 待回顾 / 待恢复 / 断节奏
- 训练页保留最关键的记录动作：主题、动作、组数、重量、次数、备注
- 回顾页强调主观感受优先，设备数据只做辅助
- 恢复页把“次日恢复”单独抬成主线，而不是附属项
- 页面之间能顺着主流程跳转，状态会保存在浏览器 localStorage 里

## 本地启动

在项目目录里执行：

```bash
npm install
npm run dev
```

默认访问：

- http://localhost:3000

## Troubleshooting

### 如果本地打开后看到 Runtime Error，例如 `Cannot find module './778.js'`

先别急着改页面代码。这个项目已经出现过一次同类问题，根因不是首页实现坏了，而是 **旧的 `next dev` 进程多开 + 端口争用 + `.next` 运行态污染**。

推荐按这个顺序排查：

1. 先看是不是同时挂了多个 `next dev` / `next start` 进程
2. 再看 `3000` 端口是不是被旧实例占着
3. 必要时停掉旧进程后清理 `.next`
4. 跑一次 `npm run build`，用来区分“源码错误”还是“运行态污染”
5. 用一个干净实例重新启动，再访问验证

这次已验证过：

- `npm run build` 成功，说明源码本体没坏
- 清理旧 dev 进程后，`next start` 在 `3001` 验证通过
- 随后 `3000` 也恢复为正常可用实例

所以如果再看到类似 `chunk.js` / `module not found` 的 Next.js 运行时报错，默认优先怀疑 **脏进程 / 脏缓存 / 端口争用**，不要一上来就改业务页面。

## 建议演示顺序

### 路线 1：直接看产品感觉
1. 打开首页 `/`
2. 先切几种演示状态
3. 看首页是不是在告诉你“现在先做什么”

### 路线 2：完整走主流程
1. 首页 `/`
2. 开始训练 `/train`
3. 结束训练，进入回顾 `/review`
4. 保存回顾，进入恢复 `/recovery`
5. 保存恢复，回到首页 `/`

## 备注

这是一个前端原型，不包含：

- 真实登录
- 真实数据库
- 真实提醒系统
- Apple Health / Apple Watch 自动同步
- 复杂训练计划编排

目标是：**今晚就能打开看感觉，确认首页和主流程是否对。**
